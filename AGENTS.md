# AGENTS.md — инструкции для агента

## С чего начать

Прежде чем вносить изменения, **прочитай спецификацию** в `docs/`. Спека описывает архитектуру, контракты между модулями и важные инварианты — без чтения кода. Код читай точечно, только те файлы, которые собираешься менять.

Спецификации разбиты по модулям (см. «Карта спецификаций» ниже). Каждая спека самодостаточна — её можно читать без остальных.

## Важные правила

### 1. Обновляй спецификацию при каждом изменении функционала

Если ты меняешь **поведение** модуля (новая фича, изменённый контракт, новый инвариант) — **обнови соответствующую спецификацию** в этом же коммите/изменении. Спека должна отражать текущее состояние кода, а не историю.

Если изменение чисто косметическое (рефакторинг без смены поведения) — спеку трогать не нужно.

### 2. Разделяй и объединяй спецификации вместе с кодом

- **При разделении модуля** на несколько — раздели и спецификацию на соответствующее количество файлов, обновив ссылки в этой карте.
- **При объединении модулей** — объедини спецификации в одну, удалив лишние файлы.

### 3. Ключевые инварианты (нарушать нельзя)

Эти правила проверены пользователем и закреплены. Если твоё изменение их нарушает — оно неправильное:

- **Неразмеченные слоги НЕ рендерятся** в превью и видео. Только отснятые (с `startMs !== null`) попадают в кадр. См. `buildTimings` и комментарий `!!! IMPORTANT`.
- **Перенос таймингов при редактировании текста** — чисто позиционный, по глобальному плоскому индексу (через границы строк), в пределах активной дорожки. См. `docs/lyrics-and-timings.md`.
- **WYSIWYG**: одна функция `renderFrame` используется и для превью, и для экспорта. Не делай раздельной логики.
- **Таймлайн**: общая линейка + waveform + ровно одна строка маркеров на каждую текстовую дорожку.
- **Drag на таймлайне**: нельзя перетащить слог раньше предыдущего или позже следующего размеченного **в той же дорожке**.
- **Дорожки**: проект содержит одну или несколько независимых текстовых дорожек (`TextTrack`); у каждой свой текст, стиль и настройки рендерера. Тайминги и редактирование — в пределах активной дорожки.

### 4. Технологический стек

- **Vite + vanilla TypeScript** (без фреймворков).
- **Mediabunny** для мьюксинга MP4 (H.264 + AAC) через WebCodecs.
- **Тесты**: Node-скрипты в `scripts/test-*.mjs`, бандлятся через esbuild. Запуск: `npm test`.
- **Браузер**: Chrome/Edge (нужен WebCodecs). Dev-сервер: `npm run dev`.

### 5. Процесс работы

1. Прочитай релевантную спецификацию из `docs/`.
2. Внеси изменение в код.
3. Обнови спецификацию, если поведение изменилось.
4. Прогони `npm test` и `npm run build`.
5. Проверь в браузере через `npm run dev`, если изменение визуальное.
