# Таймлайн

## Архитектура (модульная, стратегия)

Таймлайн разбит на модули в `src/ui/timeline/` по принципу «стратегия»: каждый тип дорожки — отдельный модуль с единым интерфейсом `TrackView`, оркестратор диспетчеризует по `track.type`. Добавление нового типа дорожки = модуль + запись в реестре, оркестратор не трогается.

- **`index.ts`** — оркестратор: canvas/DOM lifecycle, zoom, единый dispatch pointer-событий, переключатель инструментов, клавиатура (выделение слога + Del). Не содержит логики конкретных дорожек.
- **`coords.ts`** — константы (`ROW_H`, `AUDIO_ROW_H`, `RULER_H`, `TRACK_PAD`) + чистые функции раскладки (`rowHeight`, `tracksTop`, `trackTopForIndex`, `trackIndexAtY`).
- **`types.ts`** — контракты: `TimelineEnv` (msToX/xToMs/длительность/ширина/peaks + tool/pointer/dropTarget/drag/selection), `TrackDrag`, интерфейс `TrackView`.
- **`textView.ts`** — реализация `TrackView` для текстовых дорожек (маркеры слогов + drag с сохранением точки захвата).
- **`audioView.ts`** — реализация для аудиодорожек (waveform + огибающая громкости / фразы-куски в режиме редактирования).
- **`painter.ts`** — весь рендер canvas: линейка, строки (через вьюхи), строка «Фон» (фильмстрип), плейхед, таблетка записи; rAF-троттлинг перерисовки. Получает состояние оркестратора через геттеры (`PainterDeps`).
- **`gutter.ts`** — левая колонка шапок-карточек (HTML): активация, M/S, ✨/⏱, удаление; перестройка по сигнатуре.
- **`actions.ts`** — app-уровень: скрытые файловые инпуты (аудио в роль, фон), раннеры сепарации (✨) и авторасстановки (⏱).

`TrackView` (интерфейс стратегии): `rowHeight`, `draw(ctx, track, rowY, env)`, `hitTest(track, rowY, x, y, env)` → `TrackDrag | null`, `onDrag(drag, rowY, x, y, env)`, опционально `onBackgroundClick` (клик мимо объектов) и `onDoubleTap` (двойной клик). Оркестратор перебирает строки, спрашивает view о попадании; первый перехват владеет drag'ом.

## Раскладка

Таймлайн построен как аудиоредактор: **фиксированный левый gutter** (шапки) + **горизонтально-скроллируемый canvas** справа. Gutter не скроллится, canvas — да.

- **Левый gutter** (HTML, не canvas): spacer под линейку (30px), затем шапки-карточки **сплошной колонной, без зазоров**. Карточка перекрывает «свой разделитель + зазор над строкой»: высота = `rowHeight + TRACK_PAD` (`ROW_H`/`AUDIO_ROW_H`/`AUDIO_ROW_COLLAPSED_H` + 6), верх = разделитель предыдущей строки, **низ = разделитель своей строки** — каждая граница карточки совпадает с линией canvas пиксель-в-пиксель. Первая карточка начинается на 30, впритык к спейсеру (поэтому `TOP_PAD` = 10 включает зазор над первой строкой, а первая строка начинается на 36). Подпись и кнопки центрируются по **всей карточке**. Разделители строк рисуются в последний пиксель строки (`rowY + h - 1`) — для **всех** строк, включая текстовые (`textView`). **Вертикальная привязка**: `padding-top: 1px` gutter'а компенсирует рамку канваса (закреплено e2e-проверками: офсет первой шапки + попиксельное совпадение рамок карточек с разделителями, `e2e/timeline-geometry.spec.ts`). Клик по шапке → активация (`activeTrackId`). Шапки перестраиваются только при смене набора дорожек / типов / имён / активной / **привязок** (по сигнатуре), не на каждый кадр.
- **Canvas** (таймлайн): время отсчитывается **от левого края контента (x=0)**. Сверху — общая линейка (ruler), затем **одна строка на каждую дорожку** (текстовую или аудио).
- **Порядок строк = DISPLAY-порядок** (`displayTracks`): текстовая дорожка, привязанная к вокальной роли (`boundVocalRole`), рендерится **непосредственно над своим вокалом**; непривязанные текстовые — сверху в исходном порядке. Привязанная пара рисуется **одной рамкой**: у карточек классы `pair-top`/`pair-bottom` — на стыке нет границы, скруглений и разделителя canvas (`textView` не рисует линию для привязанной дорожки), бейдж «🔗» не нужен — связанность видна из слияния. При hover/активации стык закрывается акцентной рамкой (карточка выделения остаётся замкнутым прямоугольником). Модельный порядок `project.tracks` не меняется — дисплей-порядок вычисляется на отрисовке. Drag'и несут МОДЕЛЬНЫЕ индексы; оркестратор передаёт вьюхам дисплейный `rowY` + модельный индекс.

Высота canvas: `RULER_H + TOP_PAD + Σ (rowHeight(track) + TRACK_PAD)` (текстовые строки `ROW_H`, аудио `AUDIO_ROW_H`/`AUDIO_ROW_COLLAPSED_H`) **+ строка «Фон» (`BG_ROW_H`) — и всё**: канвас заканчивается ровно на нижней границе строки «Фон», без хвостового паддинга. Канвас — `box-sizing: content-box`: inline `style.height` = точная высота рисунка, рамка 1px живёт снаружи (при `border-box` контент-бокс был на 2px короче буфера, рисунок сжимался и нижние строки съезжали до ~2px относительно шапок).

### Строка «Фон» (псевдострока)

Под всеми дорожками — строка «Фон» (`BG_ROW_H`), привязанная к `project.background`, а НЕ к `Track` (типы дорожек не расширяются). В gutter — шапка «🖼 Фон» (`data-testid="track-head-background"`), на canvas — **фильмстрип** для видео-фона или статус/подсказка («фон: цвет», «фон: картинка»), без маркеров и без waveform.

- Клик по **шапке** → «выбор» псевдостроки: шапка подсвечивается, панель стиля показывает карточку «Фон» (настройки фона живут там; на мобильных сразу открывается props-sheet). Клик по шапке любой дорожки снимает выбор. Клик по **canvas-полосе** → быстрый file picker (`image/*,video/mp4`): картинка → `bgType='image'` + data URL; mp4 → `bgType='video'` + байты в `lib/backgroundVideo.ts` + `bgVideoFileName`. Логика загрузки общая — `ui/bgFile.ts: applyBgFile` (её использует и кнопка в карточке «Фон»).
- Кнопка «×» в шапке (когда загружена картинка/видео) → сброс на цвет.
- Цвет/градиент настраиваются в панели стиля (карточка «Фон (общий)»), там же индикатор видео-фона и «Вписывание».
- Геометрия: `bgRowTop(tracks) = trackTopForIndex(tracks.length, tracks)`, попадание — `isBgRowAtY`.

#### Фильмстрип видео-фона

Модуль `lib/bgThumbnails.ts`: кадры декодируются **офлайн, без воспроизведения** — mediabunny демуксирует MP4, `VideoSampleSink.samplesAtTimestamps()` декодирует по разреженным монотонным таймстемпам (WebCodecs, каждый пакет — максимум один раз, ключевые кадры делают основную работу). Одна миниатюра раз в `THUMB_INTERVAL_SEC = 2` сек (минимум), с потолком `MAX_THUMBS` (интервал растягивается на длинных видео). Результат кэшируется по идентичности объекта байтов (смена видео = новая ссылка = перестройка); построение асинхронное, по готовности таймлайн перерисовывается (`setFilmstripOnReady`).

Отрисовка: миниатюры рисуются с **родными пропорциями кадров** (высота = ряд, ширина по аспекту), левым краем в своём таймстемпе (`msToX`). Если при текущем зуме соседние кадры начали бы налезать друг на друга — лишние пропускаются (полоса естественным образом становится реже). Off-screen миниатюры отсекаются. Граница конца видео берётся из реальной длительности (`durationSec` в `BgFilmstrip`); после неё — зона цвета фона с подписью «цвет фона» (визуализация правила «видео короче песни → в конце цвет»). Пока фильмстрип строится или декод не удался — текстовый статус.

### Viewport-рендеринг (не весь контент — только видимое окно)

Канвас физически равен **ширине viewport'а** (`scroll.clientWidth`), а не полной ширине контента. Это снимает потолок по размеру backing-store: раньше при большом зуме `canvas.width = baseWidth×zoom×dpr` превышал мобильный лимит (~16000px) и канвас белел, а перерисовка waveform по всей ширине (десятки тысяч `fillRect`/кадр) тормозила воспроизведение. Теперь `canvas.width = viewportWidth × dpr` при любом зуме.

Как устроен скролл при узком канвасе:
- Внутри `.timeline-scroll` лежит обёртка-распорка `.timeline-canvas-wrap`, инлайн-`width` которой = `contentWidth` (= `viewportWidth × zoom`). Она задаёт `scrollWidth`, поэтому нативный скролл (скроллбар, touch pan-x) работает как раньше.
- Канвас `.timeline-canvas` имеет `position: sticky; left: 0` — он «прилипает» к левому краю viewport'а и всегда остаётся полностью видимым, пока раскорка прокручивается под ним.
- В `draw()` контент рисуется в **контент-пространстве** (0..contentWidth), а сдвиг видимой области делается одной строкой: `ctx.translate(-scroll.scrollLeft, 0)`. Вьюхи дорожек (`textView`, `audioView`) **ничего не знают про viewport** — они рисуют как раньше, по абсолютным X.

**Инвариант координат:** `msToX`/`xToMs` работают в контент-пространстве `[0, contentWidth]`; `env.width = contentWidth`. Видимое окно передаётся вьюхам через `env.scrollLeft` и `env.viewportWidth` — исключительно для **culling** (не рисовать off-screen слоги/пики waveform). Pointer-координаты переводятся в контент-пространство хелпером `pointerContentX(clientX) = clientX - rect.left + scroll.scrollLeft` (rect.left — левый край viewport'а, т.к. канвас sticky).

Перерисовка при скролле обязательна (нативный скролл больше не двигает пиксели): `scroll.addEventListener('scroll', scheduleDraw)` с rAF-троттлингом; `ResizeObserver` на `scroll` ловит изменение размера viewport'а (иначе на паузе канвас не подстроился бы).

## Строка текстовой дорожки

**Активная** текстовая дорожка рисуется втрое выше (`TEXT_ROW_H_ACTIVE = 3×ROW_H`): размеченные слоги раскладываются round-robin по трём полосам — 1-й слог в верхней, 2-й в средней, 3-й в нижней, 4-й снова в верхней и т.д. (нумерация — по размеченным). Неактивная — одна полоса высотой `ROW_H`. Активная дорожка подсвечена тонкой полупрозрачной полосой фона (имя — в шапке gutter).

**Неразмеченные слоги не рисуются** (инвариант — см. `docs/architecture.md`).

Каждый размеченный слог — тонкая вертикальная линия (1px, высотой в свою полосу) с текстовой меткой; полосы длительности (градиент) под слогами **не рисуются**. Зона захвата мышью (клик-выделение и drag) — **буквы**: от полоски до конца текстовой метки плюс небольшой запас (~4px; у слога без текста — узкая полоска у линии). Зона ограничена своей полосой: при трёх полосах несколько маркеров делят один x — берётся тот, под курсором (`pickMarker` lane-aware).

## Строка аудиодорожки

Только **активная** аудиодорожка рисуется высокой (`AUDIO_ROW_H`, редактируемая); остальные **сворачиваются в одну строку** (`AUDIO_ROW_COLLAPSED_H`): мини-waveform (приглушённый) с тонкой полоской automation сверху — видно, где подтянута громкость, но нельзя редактировать. Высота строки — контекстная: `rowHeight(track, activeTrackId)`; `TimelineEnv.activeTrackId` доезжает до вьюх. Клик по свёрнутой дорожке (canvas) **ничего не делает** — ни сика, ни добавления точек; активация — кликом по шапке в gutter.

В активной (высокой) строке:
- **Waveform** (пики из `AudioBuffer`, если загружено) — зеркальный, как у аудиоредактора.
- **Огибающая громкости** (volume automation) — линия поверх waveform + точки-кружки (см. ниже).

Нет отдельного «глобального» waveform-блока — каждая аудиодорожка несёт свой waveform и свою огибающую.

## Маркеры и взаимодействие

- **Инструменты для аудиострок** — переключатель в шапке таймлайна: **Автоматизация** (по умолчанию, историческое поведение: огибающая громкости) и **Редактирование** (перенос фраз между дорожками, см. ниже). Полоски automation во всех аудиостроках видны только в режиме «Автоматизация».
- **Клик по шапке дорожки** в gutter — делает дорожку активной (`activeTrackId`).
- **Drag маркера** слога (в строке текстовой дорожки) — меняет `startMs` слога.
- **Клик по маркеру слога** — выделяет его (подсветка зоны буквы + жирная метка). **Shift+клик** по другому маркеру — выделяет **диапазон** (anchor/focus по плоским индексам); захват внутри диапазона сохраняет его. С выделением работают клавиши:
  - **Del/Backspace** — убрать **тайминг** выбранного слога/диапазона: маркер снимается, тайминги хвоста сдвигаются на одну позицию назад, последний слог становится неразмеченным. **Текст не меняется** — это починка «случайного лишнего пробела» при записи (`removeTimingsAndShift`, см. `docs/lyrics-and-timings.md`). Повторный Del на том же слоге тянет хвост дальше;
  - **←/→** — нудж на ±50 мс (**Shift** — ±10 мс), для диапазона — сдвиг всего блока; соседние размеченные слоги не пересекаются (инвариант драга);
  - **Tab/Shift+Tab** — переход к следующему/предыдущему размеченному слогу (с автоскроллом видимого окна);
  - **Esc** — снять выделение. Drag маркера внутри диапазона двигает весь блок (дельтой курсора).
- **Валидатор таймингов**: слоги с нулевой/перевёрнутой длительностью или за пределами песни рисуются красным (`timingProblems`).
- **Клик/драг/двойной клик в строке аудиодорожки** — управление огибающей громкости (только инструмент «Автоматизация»; см. ниже).
- **Клик по пустому месту** на canvas — перемотка (seek).
- **Shift+колесо** — зум (с привязкой к курсору; desktop).
- **Кнопки ➖/➕ в шапке** таймлайна — пошаговый зум с якорем в центре видимой области (×1.15). Лейбл между ними показывает текущий масштаб («100%»). Работают и на тач, и на десктопе.
- **Pinch двумя пальцами** (тач) — зум с якорем в середине между пальцами; один палец по-прежнему тянет маркеры / перематывает / скроллит. Жест обрабатывается через `touchstart`/`touchmove` на `.timeline-scroll`; на время pinch флаг `isPinching` глушит pointer-drag.
- **Обычное колесо / горизонтальный свайп** — горизонтальная прокрутка.

## Ограничение перетаскивания

При drag слог нельзя перетащить **раньше предыдущего** и **позже следующего** размеченного слога **в пределах той же дорожки**. Границы вычисляются по плоскому массиву слогов перетаскиваемой дорожки: ищется ближайший размеченный слог слева и справа от текущего.

**Точка захвата сохраняется**: в момент pointerdown запоминается смещение курсора внутри маркера (`grabMs`), и drag двигает маркер на дельту курсора — линия не прыгает под курсор, даже если схватили за буквы метки.

## Volume automation (огибающая громкости)

Работает только при инструменте **«Автоматизация»**. Поверх waveform **внутри строки аудиодорожки** рисуется линия огибающей громкости (envelope) с точками-кружками (в свёрнутых строках — тонкая полоска сверху). Клик по строке активной аудиодорожки добавляет точку, перетаскивание точки меняет её время (по X) и громкость (по Y: 0=тишина внизу, 1=центр, 2=усиление вверху), двойной клик по точке — удаляет. Между точками громкость меняется линейно.

Точки хранятся в `AudioTrack.volumeAutomation: { timeMs, gain }[]` (отсортированы по времени). Хелперы — в `src/lib/volumeAutomation.ts`: `gainAtTime` (линейная интерполяция), `insertPoint`/`removePoint`/`movePoint` (иммутабельные операции), `clampGain` (диапазон 0..2).

Применение громкости **не меняет исходный `AudioBuffer`**:
- **Воспроизведение**: граф Web Audio (`MediaElementSource → GainNode → destination`). `audioEngine.applyVolumeAutomation` хранит точки; реальный gain применяется каждый кадр RAF-цикла (`gainNode.gain.value = gainAtTime(points, currentTime)`), что всегда синхронно с реальной позицией воспроизведения. Вызывается при загрузке аудио, seek и изменении точек (через store-подписку в `main.ts`, читающую активную аудиодорожку).
- **Экспорт MP4**: `renderAudioWithGain` (`OfflineAudioContext`) рендерит аудио с теми же точками офлайн → новый `AudioBuffer` подаётся в Mediabunny.

Пустой массив точек = нет автоматизации (плоский gain 1.0, исходная громкость).

## Режим редактирования стемов (перенос фраз)

Инструмент **«Редактирование»** (переключатель в шапке таймлайна) прячет огибающие громкости и превращает активную аудиодорожку в набор **фраз-кусков**: на ней подсвечиваются диапазоны звука, окружённого относительной тишиной (детект — `lib/audioChunks.ts`, energy-VAD с гистерезисом: окна 20 мс, порог 6% от пикового RMS, паузы короче 160 мс не разрезают, куски короче 100 мс отбрасываются, края паддируются на 30 мс; кеш по идентичности буфера).

- Кусок можно **навести** (подсветка) и **перетащить на другую аудиодорожку** — куда отпустил, туда фраза и замешалась (акцентная полоса на строке-приёмнике показывает, куда встанет; строка «Оригинал» подсвечивается красным — туда нельзя). Drop на исходную дорожку — no-op.
- Захват — **только прямоугольником куска** на активной строке (по вертикали — пределы строки, по горизонтали — диапазон куска). Клик в любом другом месте canvas (линейка, другие строки, тишина между кусками) — обычная перемотка; клик по самому куску без переноса — no-op.
- Разрешены только роли **лид / минус / бэк** (и как источник, и как приёмник). «Оригинал» не редактируется — это reference, по которому работали сепаратор и выравниватель.
- Сам перенос (PCM-хирургия: обнулить диапазон в источнике, подмешать в приёмник на той же позиции, перезагрузить обе роли через `audioLoader`) — `lib/audioEdit.ts: moveChunkToRole`, см. `docs/audio.md`.
- Клик по пустому месту строки в этом режиме — перемотка (точки автоматизации не добавляются).
- Отмены (undo) нет; вернуть фразу можно обратным перетаскиванием.

Механика в архитектуре стратегий: `TrackDrag` вида `'chunk'` (несёт `startMs/endMs`), опциональный `TrackView.onDrop(drag, targetTrack, env)` вызывается оркестратором на pointerup со строкой под курсором; оркестратор трекает `env.pointer` (hover) и `env.dropTargetTrackId` (индикатор drop) для всех вьюх.

## Playhead

Красная вертикальная линия (2px), позиция = текущее время воспроизведения. При записи — «таблетка» с текстом следующего слога справа от плейхеда (в области активной **текстовой** дорожки).

## Запись таймингов

Запись всегда идёт для **активной текстовой дорожки** (аудиодорожки нельзя записывать). В режиме записи рядом с плейхедом показывается следующий слог активной дорожки для отснимания. Нажатие Space (через `timing.ts`) присваивает `startMs` слогу активной дорожки.
