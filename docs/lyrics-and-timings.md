# Текст и тайминги

## Парсер (`src/lib/textParser.ts`)

Разбиение текста на слоги:
- **Разделители**: пробел (и таб), `/`, перенос строки.
- **Всё остальное** (буквы, цифры, пунктуация `. , ! ?`) остаётся частью слога.
- Несколько разделителей подряд схлопываются (нет пустых слогов).

Каждый слог хранит `sep` — разделитель, который шёл перед ним (`' '` для пробела, `'/'` для слэша, `''` для первого в строке). Это даёт точный round-trip: `serializeLyrics` восстанавливает оригинальный текст (пробелы остаются пробелами, слэши — слэшами).

## Модель данных

```ts
Syllable { text: string; startMs: number | null; sep?: string }
Line { syllables: Syllable[] }
```

`startMs` — момент начала заливки слога. `null` = неразмещённый. Конец слога определяется в `buildTimings`:
- середина строки: конец = старт следующего слога (в той же строке);
- **последний слог строки**: конец = `startMs + 500мс` (фиксированная короткая заливка, чтобы слог не тянулся медленно через паузу до следующей строки);
- последний слог песни: конец = длительность песни (заливается полностью).

Таймлайн рисует полосу длительности градиентом до следующего слога в той же дорожке (визуально), но фактическая заливка в кадре идёт по `buildTimings`.

## Перенос таймингов при редактировании (`mergeTimings`)

**Чисто позиционный перенос по глобальному плоскому индексу, в пределах активной дорожки.**

При каждом изменении текста в редакторе (который всегда редактирует активную дорожку):
1. Текст парсится заново → `newLines`.
2. `mergeTimings(track.lines, newLines)` переносит тайминги.
3. Все слоги (старые и новые) объединяются в плоский массив.
4. Слог `i` в новом массиве получает тайминг слога `i` в старом массиве.
5. Если новых слогов больше (разбиение) — последний становится `null`.

Пример: `[а(100), б(200), в(300)]` → разбили «а» → `[а1, а2, б, в]`:
`а1←100, а2←200, б←300, в→null`.

**Перенос пересекает границы строк** — слоги из разных строк одной дорожки участвуют в одном плоском массиве. Тайминги **никогда не переносятся между дорожками** — каждая дорожка независима.

## Съёмка таймингов (`src/lib/timing.ts`)

Режим записи всегда работает с **активной дорожкой**: играет аудио, текущее время становится `startMs` следующего неразмеченного слога активной дорожки. Указатель продвигается по порядку. `Esc` — выход. Переключение активной дорожки сбрасывает курсор на первый неразмеченный слог новой дорожки при следующем `start()`.

Запуск stamp: на desktop — **Space** (внутренний keydown-обработчик в capture-фазе). На мобильном — **тап по overlay превью**: `.rec-overlay` в `src/ui/preview.ts` слушает `pointerdown` и вызывает тот же публичный `timingCapture.stampNow()`. Оба пути идентичны — `stampNow()` читает `audioEngine.currentTimeMs` и пишет в активную текстовую дорожку. Кнопка «Запись таймингов» (`src/ui/controls.ts`) блокируется, когда активная дорожка не текстовая, с попапом-подсказкой.

## `flatSyllables(lines)`

Преобразует `Line[]` в плоский массив `{ lineIndex, sylIndex, syl }` в порядке чтения. Вызывается per-track (таймлайн и съёмка передают `track.lines`).

## `nextUntimedIndex(lines)`

Индекс следующего неразмеченного слога в плоском массиве (для съёмки).

## Авторасстановка таймингов (`src/lib/forcedAlign.ts` + `src/lib/alignment/ctc.ts`)

Кнопка «⏱» в шапке **текстовой** дорожки на таймлайне: CTC forced alignment
текста дорожки против вокального аудио. Источник аудио — по приоритету
`lead` → `original` → `back` (основной путь: разделение оригинала даёт лид;
для импортированного KFN вокал может лежать в бэке). Существующие тайминги
дорожки **перезаписываются целиком**.

Пайплайн: вокал → 16 кГц моно (нормализация zero-mean/unit-var) → wav2vec2
CTC-модель (**`wav2vec2-large-960h-lv60-self` fp16, ~630 МБ**, наш экспорт —
`eval/export-large-align.py`, хостится на HF `Project42/wav2vec2-large-lv60-align`;
качается и кэшируется в Cache Storage, как Mel-RoFormer) → инференс ЧАНКАМИ
по 30 с с перекрытием 2 с (внимание модели не тянет всю песню; 16 с проверены —
хуже: теряется контекст на повторах) → склейка логитов → Viterbi-выравнивание
транскрипта (порт torchaudio `forced_align`) → спаны слов → стартовые времена
слогов (внутри слова распределяются по «весу» букв; стратегия `proportional`
по умолчанию). Вся чистая математика — в `alignment/ctc.ts`, покрыта юнит-тестами
без модели.

**Бенчмарк на Kiri** (эталон — тайминги KFN, пословно, наш лид-стем): median
113 мс, p90 247 мс, 91% слов ≤250 мс, 97% ≤500 мс, худшее слово 0.6 с. Базовая
модель (base-960h) давала p90 8.3 с — путала повторяющиеся припевы; large
различает вхождения повторов.

Английская модель (32-токенный словарь в `ctc.ts`); для других языков нужен
другой чекпойнт — интерфейс модель-агностичен, сравнивать модели можно через
`eval/` (см. `eval/README.md`; там же проверка пригодности аудио
`verify-stem.mjs` и фикстуры-эталоны из KFN).
