# Текст и тайминги

## Парсер (`src/lib/textParser.ts`)

Разбиение текста на слоги:
- **Разделители**: пробел (и таб), `/`, перенос строки.
- **Всё остальное** (буквы, цифры, пунктуация `. , ! ?`) остаётся частью слога.
- Несколько разделителей подряд схлопываются (нет пустых слогов).

Каждый слог хранит `sep` — разделитель, который шёл перед ним (`' '` для пробела, `'/'` для слэша, `''` для первого в строке). Это даёт точный round-trip: `serializeLyrics` восстанавливает оригинальный текст (пробелы остаются пробелами, слэши — слэшами).

## Модель данных

```ts
Syllable { text: string; startMs: number | null; sep?: string }
Line { syllables: Syllable[] }
```

`startMs` — момент начала заливки слога. `null` = неразмещённый. Конец слога определяется в `buildTimings`:
- середина строки: конец = старт следующего слога (в той же строке);
- **последний слог строки**: конец = `startMs + 500мс` (фиксированная короткая заливка, чтобы слог не тянулся медленно через паузу до следующей строки);
- последний слог песни: тоже `startMs + 500мс` (как конец строки) — не тянется медленно через аутро.

Таймлайн рисует полосу длительности градиентом до следующего слога в той же дорожке (визуально), но фактическая заливка в кадре идёт по `buildTimings`.

## Перенос таймингов при редактировании (`mergeTimings`)

**Чисто позиционный перенос по глобальному плоскому индексу, в пределах активной дорожки.**

При каждом изменении текста в редакторе (который всегда редактирует активную дорожку):
1. Текст парсится заново → `newLines`.
2. `mergeTimings(track.lines, newLines)` переносит тайминги.
3. Все слоги (старые и новые) объединяются в плоский массив.
4. Слог `i` в новом массиве получает тайминг слога `i` в старом массиве.
5. Если новых слогов больше (разбиение) — последний становится `null`.

Пример: `[а(100), б(200), в(300)]` → разбили «а» → `[а1, а2, б, в]`:
`а1←100, а2←200, б←300, в→null`.

**Перенос пересекает границы строк** — слоги из разных строк одной дорожки участвуют в одном плоском массиве. Тайминги **никогда не переносятся между дорожками** — каждая дорожка независима.

## Снятие таймингов выделением (`removeTimingsAndShift`)

Del на выбранном маркере таймлайна убирает **тайминг**, а не слог: текст остаётся нетронутым, тайминги всех последующих слогов сдвигаются на одну позицию назад, последний слог становится неразмеченным. Для диапазона — сдвиг на его длину. Это позиционный эффект «удалить слог из текста», применённый только к таймингам — починка ситуации, когда при записи случайно нажали пробел лишний раз: с этого места тайминги «обгоняли» текст на один, и удаление одного маркера выравнивает весь хвост. Хелпер чистый (иммутабельный, возвращает новый массив `Line[]`), живёт в `textParser.ts`, покрыт юнит-тестами. Снять сам слог из текста — операция редактора текста (там работает `mergeTimings`).

## Клавиатурная правка таймингов

Выделение на таймлайне — `anchor/focus` по **плоским индексам** дорожки (`SyllableSelection`): клик — одиночное, Shift+клик — диапазон. Операции (все уважают инвариант «не пересекать соседние размеченные слоги»):

- **←/→** — нудж ±50 мс (Shift — ±10 мс); для диапазона — сдвиг блока одним сдвигом (`rangeShiftBounds` считает допустимые границы по внешним соседям и `[0, duration]`).
- **Tab/Shift+Tab** — переход к следующему/предыдущему **размеченному** слогу (неразмеченные пропускаются), окно таймлайна автоскроллится.
- **Del/Backspace** — снять тайминг выделения (слог или диапазон), хвост сдвигается назад (см. ниже `removeTimingsAndShift`).
- Drag маркера внутри активного диапазона двигает весь блок: дельта курсора применяется к снапшоту исходных таймингов (снимается при первом движении).

**Валидатор** (`timingProblems`): размеченный слог «плохой», если его старт не строго больше старта предыдущего размеченного (нулевая/отрицательная длительность, перехлёст) или выходит за `durationMs`. Плохие рисуются на таймлайне красным (маркер + метка); отмечается более поздний слог пары.

## Съёмка таймингов (`src/lib/timing.ts`)

Режим записи всегда работает с **активной дорожкой**: играет аудио с текущей позиции, каждое нажатие ставит текущее время как `startMs` слога под курсором и двигает курсор вперёд. Слоги **перезаписываются по ходу** — прежние тайминги не очищаются заранее (остановившись раньше, ты теряешь только то, что успел перезаписать).

**Курсор при старте сеется от плейхеда**: первый слог с `startMs ≥ позиция − 200 мс`. Поставить плейхед в середину/конец песни и нажать «Запись» значит «перезапишу хвост отсюда» — главный сценарий после авторазстановки, когда размечено всё, а вручную правится кусок. Допуск 200 мс: плейхед ровно на маркере → «с этого слога»; посреди слога → «с текущего звучащего». Фолбэки: впереди нет размеченных слогов → первый неразмеченный (продолжение незавершённой съёмки); размечено всё и плейхед в конце → курсор за последним слогом (первое же нажатие завершает запись).

`Esc` — выход из записи. Запуск stamp: на desktop — **Space** (внутренний keydown-обработчик в capture-фазе). На мобильном — **тап по overlay превью**: `.rec-overlay` в `src/ui/preview.ts` слушает `pointerdown` и вызывает тот же публичный `timingCapture.stampNow()`. Оба пути идентичны — `stampNow()` читает `audioEngine.currentTimeMs` и пишет в активную текстовую дорожку. Кнопка «Запись таймингов» (`src/ui/controls.ts`) блокируется, когда активная дорожка не текстовая, с попапом-подсказкой. Явный `start(fromIndex)` (очистить хвост и переснять с конкретного слога) публично доступен, но из UI сейчас не вызывается.

## `flatSyllables(lines)`

Преобразует `Line[]` в плоский массив `{ lineIndex, sylIndex, syl }` в порядке чтения. Вызывается per-track (таймлайн и съёмка передают `track.lines`).

## `nextUntimedIndex(lines)`

Индекс следующего неразмеченного слога в плоском массиве (для съёмки).

## Авторасстановка таймингов (`src/lib/forcedAlign.ts` + `src/lib/alignment/ctc.ts`)

Кнопка «⏱» в шапке **текстовой** дорожки на таймлайне: CTC forced alignment
текста дорожки против вокального аудио. Источник аудио — **жёсткая привязка**
`TextTrack.boundVocalRole`: ровно этот вокал и никакой другой. Непривязанная
дорожка (добавленная через «+», импортированная из KFN) при нажатии ⏱
открывает диалог выбора вокальной дорожки (кнопки с именами: Вокал/Бэк/
Оригинал; минус не предлагается); выбор **сохраняет** привязку. Один вокал —
максимум одна привязанная текстовая дорожка: конфликт показывает инлайн-ошибку
с именем соперника. Дефолтная дорожка нового проекта привязана к «Вокал»
(lead). Существующие тайминги дорожки **перезаписываются целиком**.

Пайплайн: вокал → 16 кГц моно (нормализация zero-mean/unit-var) → wav2vec2
CTC-модель → инференс ЧАНКАМИ по 30 с с перекрытием 2 с (внимание модели не
тянет всю песню; 16 с проверены — хуже: теряется контекст на повторах) →
склейка логитов → Viterbi-выравнивание транскрипта (порт torchaudio
`forced_align`) → спаны слов → стартовые времена слогов (внутри слова
распределяются по «весу» букв — для мультиязычной модели вес считается по
романизированным буквам; стратегия `proportional` по умолчанию). Вся чистая
математика — в `alignment/ctc.ts`, покрыта юнит-тестами без модели.

### Реестр моделей и автоопределение (`src/lib/alignment/models.ts`)

Модель выбирается **автоматически по тексту дорожки** (`pickAlignModel`):
любая не-ASCII буква (кириллица, умлауты) → мультиязычная, чистый ASCII-латиница
→ английская. Обе модели — один и тот же wav2vec2-CTC ONNX-интерфейс (16 кГц,
кадр на 320 сэмплов):

| Модель | Чекпойнт | Словарь | Сепаратор слов |
|---|---|---|---|
| **английская** (дефолт для ASCII) | `wav2vec2-large-960h-lv60-self` fp16 ~630 МБ (`eval/export-large-align.py`, HF `Project42/wav2vec2-large-lv60-align`) | 32 токена, ВЕРХНИЙ регистр A–Z + `'` | `\|` (id 4) |
| **мультиязычная** | MMS-300M aligner (1130 языков; конверсия `MahmoudAshraf/mms-300m-1130-forced-aligner`, наш экспорт `eval/export-mms-align.py`, HF `Project42/mms-300m-align`) fp16 ~600 МБ | 31 токен, строчные a–z + `'` | нет |

Токенизация модель-зависима (`buildWords(flat, model)`): регистр, словарь и
**романизация** (для MMS — uroman-порт `alignment/romanize.ts`: кириллица →
латиница, слово-скоуп правила — «е»→ye в начале слова, диграфы ие→iye/ое→oye,
ъ/ь отбрасываются, «-ий» в конце → y, умлауты ae/oe/ue, ß→ss). У MMS нет
токена-разделителя слов — слова в транскрипте идут подряд (монотонный Viterbi
сохраняет порядок). **Лицензия весов MMS: CC-BY-NC-4.0** (некоммерческое
использование). Веса обеих моделей качаются в Cache Storage по своим бакетам.

**Бенчмарк на Kiri** (эталон — тайминги KFN, пословно, наш лид-стем; английская
модель): median 113 мс, p90 247 мс, 91% слов ≤250 мс, 97% ≤500 мс, худшее
слово 0.6 с. Базовая модель (base-960h) давала p90 8.3 с — путала повторяющиеся
припевы; large различает вхождения повторов. Мультиязычная модель на английском
не бенчмаркалась (для ASCII-текста используется английская); сравнивать модели
можно через `eval/` (см. `eval/README.md`; там же проверка пригодности аудио
`verify-stem.mjs` и фикстуры-эталоны из KFN). Хук для подмены URL в eval —
`setAlignmentModelOverride` (применяется только к английскому слоту).
