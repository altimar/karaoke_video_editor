# Аудио

## Роли аудиодорожек

Проект содержит четыре фиксированные аудиодорожки (роли): **оригинал** (полный reference-микс, для записи таймингов), **вокал** (lead — голос певца, извлекается Mel-RoFormer; звучит в редакторе, но **не** попадает в экспорт видео), **минус** (instrumental — микшируется в экспорт видео) и **бэк** (бэк-вокал — тоже в экспорт). Роли заданы в модели (`AudioTrack.role: 'original' | 'lead' | 'minus' | 'back'`); имена фиксированы и не редактируются. Аудио в роль загружается кликом по её шапке в таймлайне (пустая → диалог загрузки).

Сырые байты аудио хранятся ВНЕ проекта (в `audioLoader`); дорожка хранит только `audioFileName` + `volumeAutomation`.

## AudioEngine (`src/lib/audioEngine.ts`) — мульти-голос

Каждая загруженная роль — «голос» (voice): `<audio>` → `MediaElementSource` → `GainNode` → общий `ctx.destination`. Голоса суммируются на destination. Один общий `AudioContext`.

- `loadBytes(role, bytes, filename)` — загрузить/заменить аудио в роли.
- `clear(role)` — выгрузить аудио роли (слот остаётся).
- `getBuffer(role)` — декодированный `AudioBuffer` роли (для экспорта/waveform).
- `applyVolumeAutomation(role, points)` — огибающая громкости роли (gain применяется каждый кадр RAF).

### Режимы воспроизведения

Два режима выбирают, какие голоса звучат:
- **playback** (`play()`): вокал + минус + бэк (если хоть один загружен), иначе оригинал. Lead слышен в редакторе для удобства, но в экспорт видео не попадает. Используется кнопкой «Пуск».
- **record** (`playForRecord()`): оригинал (если загружен), иначе вокал + минус + бэк. Используется записью таймингов.

Все стартующие голоса начинают одновременно из одной позиции. `currentTimeMs`/`durationMs` — по первому голосу активного набора.

## audioLoader (`src/lib/audioLoader.ts`)

Мост между UI и моделью: `loadAudioIntoRole(role, file)` (декодирует + хранит байты + обновляет `audioFileName`), `loadAudioBytesIntoRole(role, bytes, filename)` (то же, но из готовых байтов — используется сепаратором), `clearAudioRole(role)`, `getAudioBytesMap()` (для экспорта — байты по ролям).

## Извлечение вокала/минуса/бэка из оригинала (двухфазная сепарация)

Если загружен «оригинал», а «вокал» или «минус» пуст — в шапке соответствующей дорожки на таймлайне появляется кнопка **✨**. Один клик запускает **две модели последовательно** (прогресс общий, фазы различаются статус-строкой «Этап 1/2», «Этап 2/2»):

1. **Фаза 1 — вокал + минус** (VOCALS_MODEL): вокальная маска → стем вокала; минус = `mix − vocals`.
2. **Фаза 2 — лид + бэк** (KARAOKE_MODEL): вокальный стем → маска лида; бэк = `vocals − lead`.

Результат заполняет **три** роли: «вокал» (лид), «бэк», «минус». Реализация: `separateFull()` в `src/lib/separation.ts` + модальный прогресс `src/ui/separationDialog.ts`.

### Формат стемов

Стемы — **WAV PCM 16 бит 44.1 кГц** (без потерь): перенос фраз между дорожками перекодирует PCM→PCM без поколенческих потерь. Сжатие в **MP3 192 kbps** происходит только при **экспорте в KFN** (`src/lib/mp3Encoder.ts`, чистый JS-порт LAME; уже-mp3 файлы вшиваются как есть, без перекодирования; сбой кодирования — файл как есть). MP3 — родной формат KaraFun (его собственные .kfn содержат mp3); AAC/m4a плеером KaraFun не проигрывался.

### Детект «нет бэк-вокала» (`src/lib/backDetect.ts`)

Во многих песнях бэк-вокала нет вообще, но фаза 2 всё равно вырывает в бэк тихий остаток лида («везде очень тихо»). После фазы 2 стем бэка проверяется (`detectBackingVocals`): если он тише лида **в среднем более чем на −15 дБ** И **даже в самом громком 100-мс окне тише на −9 дБ** — это утечка. Тогда:

- стем бэка **не создаётся** (`SeparationResult.back = null` — таймлайн и мастер оставляют слот «Бэк» пустым и сообщают тостом);
- лидом становится **весь вокальный стем фазы 1** — из лида ничего не вырезается (фразы, «уехавшие» в бэк, остаются в вокале).

Пороги подобраны консервативно (ошибка «удержать лишний стем» лучше, чем «потерять настоящий бэк»): реальный бэк даже в тихом миксе поднимается в припевах (пиковый критерий его спасает).

- **Модель фазы 1**: Mel-Band RoFormer (веса «Kim Vocal 2» SYHFT, репозиторий `musetric/vocal-separation-roformer-onnx`), host-STFT экспорт: вход `[1, 2050, 1101, 2]` (bins-major: `((2f+ch)·T + t)·2 + ri`), выход — комплексная маска той же формы (flat). STFT/iSTFT делает редактор (`src/lib/stft.ts`, FFT + periodic Hann, `n_fft=2048`, `hop=441`, `center=True`). Два файла: `.onnx` (~5 МБ) + `.onnx.data` (~700 МБ fp16, external-data, путь `syhft_core_folded_fp16_webgpu.onnx.data` без `./`), кеш `demucs-model-v1`.
- **Модель фазы 2**: aufr33/viperx **karaoke** («RoFormer Lead/Back», SDR 10.19), ONNX-экспорт bdsqlsz, **перезаписанный графовой хирургией** (`eval/fix-karaoke-onnx.mjs`): `Einsum` → MatMul/Mul/Transpose, широкие `Split` (60 выходов mel-полос) → бинарные деревья 2-выходных Split'ов. Причина: нативный экспорт порождает шейдеры с 11+ storage-буферами при лимите WebGPU в 10. Переписанный граф численно идентичен (maxAbsDiff = 0). Вход `[1, T, 4100]` (frames-major: `t·4100 + (2f+ch)·2 + ri`), выход `[1, 1, 2050, T, 2]` (stem, одна маска = лид). Один файл ~876 МБ fp32, кеш `karaoke-model-v1`. **Хостинг**: HF-зеркало `Project42/mel-band-roformer-karaoke-webgpu` (наш аккаунт).
- **Память**: сессии моделей **никогда не живут одновременно** (каждая ~0.7–0.9 ГБ весов) — single-slot кеш (`liveSession`), фаза 1 делает `release()` до создания сессии фазы 2. Пик ≈ 0.9 ГБ + активации.
- **Layouts моделей** описаны в `ModelConfig` (`inputLayout`/`maskLayout`); упаковка/распаковка — `packStft`/`applyMask` (покрыты юнит-тестами, `tests/separation-layout.test.ts`).
- **Версия ORT критична**: нужен **`onnxruntime-web@1.29.0-dev.20260724-ed98916356`** (dev-сборка, что использует musetric). Стабильная 1.21 падает при создании сессии с голым числовым кодом — граф использует ops/форматы, поддерживаемые только в 1.29. URL зашит в `ORT_CDN_URL` (`src/lib/separation.ts`).
- **Чанкинг**: обе модели жуют окна ~11 с (`chunkSamples = 441×1100 = 485100`), шаг 8 с (`352800`, ~73 % окна), перекрытие ~3 с. По чанкам — track-level overlap-add с окном Хэмминга (общий `runMaskModel`).
- **Адаптивное окно karaoke-модели**: её attention материализует `60 полос × 8 голов × T² × 4 байта` в **одном** GPU-буфере — при T=1101 это 2.33 ГБ. Лимит WebGPU `maxBufferSize` на Windows/D3D12 — 2 ГиБ, `CreateBuffer` падает ошибкой валидации (на macOS/Metal лимит выше — там работает полный кадр). `resolveFrames()` (в `separation.ts`) меряет лимит адаптера (`navigator.gpu.requestAdapter().limits.maxBufferSize`) и, если полный кадр не влезает, ужимает окно с запасом `ATTENTION_HEADROOM = 2` (несколько attention-буферов живут одновременно + ~0.9 ГБ весов): на 2-ГиБ адаптерах T=747 (~7.5 с; проверено на RTX 3070 пробой `eval/run-karaoke-frames-probe.mjs`). Память квадратична по T, поэтому уменьшение окна сильно снижает расход. Модель фазы 1 имеет **статический** вход `[1,2050,1101,2]` (fused `MultiHeadAttention`) — всегда полный кадр, её буферы в лимит влезают. Короткие финальные чанки добираются нулями (`packStft`/`applyMask` принимают ёмкостный `frames`, маска лежит по заполненному T).
- **Варианты модели фазы 2** (⚙ Настройки): `fp32`-оригинал (~876 МБ, дефолт) и **облегчённая fp16** (~440 МБ; конвертация исходной bdsqlsz-модели → fp16, затем та же графовая хирургия). fp16 вдвое легче по видеопамяти и быстрее — помогает на 4 ГБ-картах при сбоях `device lost`/TDR; кеши у вариантов раздельные.
- **Ошибки извлечения** (`ui/separationError.ts`): известные GPU-паттерны (device lost, invalid buffer/mapAsync, OOM, обрыв скачивания) переводятся в человеко-читаемое сообщение с советом; исходный текст — под катом «Подробности»; если включена не fp16 — кнопка «Переключиться на облегчённую модель».
- **Требования**: нужен **WebGPU** (`navigator.gpu`) и Cache Storage. ORT сам строит GPU-дескриптор — **не переопределять** `env.webgpu.device`. `getSeparationStatus()` возвращает человекочитаемую причину; кнопка ✨ показывается всегда (когда lead или minus пусты и оригинал загружен), при недоступности — toast с причиной. Вход аудио ресемплицся до 44100 Hz stereo через `OfflineAudioContext`.
- **Ограничения** (учтены в дизайне): STFT/маски/iSTFT считаются на main thread чистым JS (round-trip SNR ~142 дБ, см. `tests/stft.test.ts`); **отмены нет** — попап не закрывается до завершения. Будущие задачи: вынос в Web Worker + честная отмена.

## Mute / Solo (только аудиодорожки)

В шапке каждой аудиодорожки на таймлайне есть кнопки **M** (mute) и **S** (solo):

- **Mute (M)**: заглушает роль (gain = 0). Заглушенная роль не звучит при воспроизведении и **не попадает в экспорт MP4**.
- **Solo (S)**: если хотя бы одна роль в соло — слышны/экспортируются только роли в соло, остальные приглушаются. Несколько ролей можно поставить в соло одновременно.
- Флаги хранятся в модели (`AudioTrack.muted`, `AudioTrack.solo`), сериализуются в проект-файл. В `audioEngine` применяются как множитель gain поверх огибающей громкости (через `setMuteSolo` + `roleGain`). Общая логика «слышимости» роли — `isRoleAudible(project, role)` (`src/types.ts`): роль слышна, если не muted и (нет ни одного solo ИЛИ она сама в solo). Эту же функцию использует экспорт MP4 при выборе стемов.
- Экспорт MP4 микширует роли `lead`/`minus`/`back` (каждую со своей volume automation), фильтруя по `isRoleAudible`. `original` в экспорт никогда не попадает. KFN-экспорт не зависит от mute/solo (там фиксированные слоты minus/back).

## Редактирование стемов: перенос фраз между ролями

Сепаратор иногда путает лид и бэк (или замешивает инструмент в бэк). Инструмент таймлайна **«Редактирование»** позволяет перетащить фразу-кусок с одной аудиодорожки на другую — по одной или рамочным выделением сразу несколько (интерактив — `docs/timeline.md`); фактический перенос делает `src/lib/audioEdit.ts`:

- **Детект кусков** (`src/lib/audioChunks.ts`): energy-VAD по каналам буфера — фразы = непрерывный звук между относительными паузами. Чистое ядро на `Float32Array[]` (тестируется в Node), обёртка `detectChunks(buffer)` кешируется по идентичности буфера (как пики waveform).
- **Перенос** (`moveChunkRangesToRole(fromRole, toRole, ranges)` — батч для рамочного мультивыделения; `moveChunkToRole(fromRole, toRole, startMs, endMs)` — вырожденный случай одного диапазона): чистое ядро `moveSamplesRanges` (для одного диапазона — `moveSamples`) — каждый диапазон обнуляется в копии источника и **суммируется** («замешивается») в приёмник на той же временной позиции (приёмник короче — дорастает нулями; разные sample rate — линейный ресемпл каждого куска; число каналов приводится к приёмнику, более широкий кусок усредняется). Обе роли пере-кодируются в WAV (`encodeWavChannels`, PCM→PCM без потерь — см. «Формат стемов») и загружаются обратно через `loadAudioBytesIntoRole` — воспроизведение, waveform, экспорт и save/load видят результат без спец-логики. Позиция воспроизведения (и сам проигрывавшийся микс) восстанавливаются после перезагрузки голосов.
- **Роли**: редактируются только `lead` / `minus` / `back`. `original` — неприкосновенный reference (по нему работают сепарация и выравнивание). Имена файлов ролей сохраняются; пустой приёмник наследует имя источника.
- Volume automation ролей не трогается (огибающие применяются поверх нового аудио как обычно). Undo нет — обратный перенос делается вручную.

## Смена проекта

Открытие другого проекта (📂 .karaokeproject/.kfn) **останавливает всё воспроизведение** (`audioEngine.stopAll` — пауза каждому загруженному голосу, сброс активного набора) и **выгружает роли, которых в новом проекте нет** (`clearRolesAbsentFrom`): аудио предыдущего проекта не может «протекать» в новый. Мастер нового проекта чистит все роли явно (`clearAudioRole` по каждой).

## Плавные часы воспроизведения

`HTMLMediaElement.currentTime` обновляется в Chrome **грубыми ступеньками** (~20–40 мс) — при чтении «как есть» каждый RAF-кадр анимации (скроллер превью, плейхед таймлайна) заметно дёргается. `audioEngine.currentTimeMs` поэтому **экстраполирует**: точка отсчёта (wall-часы + аудиопозиция) ставится на старте/сике/смене скорости, между чтениями время считается через `performance.now() × playbackRate`, каждое чтение мягко подтягивает оценку к реальным часам (5% ошибки), а расхождение > 40 мс — жёсткий ресинк (seek/loop). В паузе возвращается сырое значение (оно точное). Экспорт MP4 от этого не зависит: его кадры идут по равномерной сетке `i/fps`.

## События

- `onAudioState(fn)` — play/pause.
- `onTime(fn)` — текущее время (RAF-цикл во время воспроизведения).
